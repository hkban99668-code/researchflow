# 离线重排评测（T-030，2026-10-17）

对已标注的候选池（T-028 修复后重跑的 `pool_r2.json` / `pool_hard_r2.json`，评委 gemini×GLM 严格口径），把每个课题池里的全部候选按不同方式重排，直接用现有标签打分。嵌入：百炼 `text-embedding-v4`（单批上限 10）。查询用课题原文（中文），候选是标题 + 摘要切块（多数为英文）。一次评测约 7 万嵌入 token。

| 课题集 | 方法 | Recall@5 | Recall@10 | Precision@5 | MRR |
| --- | --- | --- | --- | --- | --- |
| 简单（20） | BM25 | 0.406 | 0.739 | 0.840 | 0.938 |
| | 向量 | 0.450 | 0.835 | 0.880 | 0.975 |
| | 混合 RRF | 0.448 | 0.812 | 0.890 | 0.950 |
| | （对照）关键词检索 | 0.412 | 0.741 | 0.830 | 0.913 |
| 困难（20） | BM25 | 0.183 | 0.304 | 0.320 | 0.553 |
| | **向量** | **0.559** | **0.858** | **0.830** | **0.950** |
| | 混合 RRF | 0.270 | 0.657 | 0.440 | 0.631 |
| | （对照）关键词检索 | 0.175 | 0.313 | 0.310 | 0.509 |
| | （对照）检索 Agent | 0.611 | 0.728 | 0.930 | 0.950 |

## 结论
- **混合不总是更好。** 简单课题上三种重排差不多，混合略好于 BM25。困难课题上，向量重排把 Precision@5 从 0.31 拉到 0.83，而等权 RRF 混合只有 0.44：BM25 那一路几乎失效（中文口语查询对英文摘要，字二元组与英文词没有重叠），等权融合把向量的好排名拖下来了。
- 向量重排的效果接近检索 Agent（0.83 vs 0.93），而它不需要调用大模型、只花嵌入费用。可以作为 Agent 之外的便宜方案，或作为 Agent 之后的第二层。
- 只是重排池内候选：任何方法的上限是池内已有的相关文献（报告里的"池内理论最大 Recall"=1.0）。

## 下一步（已记入待办）
- 融合要感知查询与文档的语言/词面重叠：例如 BM25 用 Agent 改写后的英文查询，或按两路各自的置信度加权，而不是等权 RRF。
- 每个课题向量被嵌入了两次（混合与纯向量各一次），可复用。

## 局限
单次运行；模型评委标签；课题由 Claude 设计；重排只在已有候选内进行。

## T-031 之后：adaptive 融合（2026-10-17）

融合前先算 BM25 一路的词面覆盖率，覆盖低就把它的权重降下来（覆盖为 0 时等于纯向量）。真实嵌入重跑：

| 课题集 | 等权 RRF | adaptive | 纯向量 | BM25 |
| --- | --- | --- | --- | --- |
| 困难 Precision@5 | 0.44 | **0.83** | 0.83 | 0.32 |
| 简单 Precision@5 | 0.89 | 0.88 | 0.88 | 0.84 |

- adaptive 消除了等权融合在困难课题上的损害（0.44 → 0.83），但在这两套课题上**没有超过纯向量**：BM25 这一路在当前查询（中文课题原文）下几乎贡献不了排序信息。诚实的结论是"自适应融合能避免拖后腿，但 BM25 在这里没有增益"。
- 多查询（加入检索 Agent 改写的英文查询）要等重建候选池、写入 `agent_queries` 后才能评；现有池里没有这个字段，`hybrid_multiquery` 与 `adaptive` 结果相同。这是让 BM25 真正发挥作用的那一步（英文改写查询对英文摘要有词面重叠）。
- 评测里每个方法各嵌入一次查询与候选，一次评测嵌入约 11~14 万 token；可以按课题缓存向量，留作优化。

## 多查询融合（2026-10-17，重建困难池 `pool_hard_r3.json`，含 Agent 改写查询）

重建困难课题候选池（345 条候选，评委 gemini×GLM 一致率 95.7%、κ 0.91；这次 20 个课题的检索 Agent 全部正常结束，Agent 自己选的前 5 条 Precision@5 = 1.00，逐课题对关键词检索 19 胜 0 负 1 平）。查询集合 = 课题原文 + Agent 改写的英文查询，BM25 与向量各取每篇文献在各查询下的最好排名，再按覆盖率自适应融合。

| 方法 | Recall@5 | Recall@10 | Precision@5 | MRR |
| --- | --- | --- | --- | --- |
| BM25（原文） | 0.184 | 0.290 | 0.340 | 0.553 |
| 纯向量（原文） | 0.541 | 0.866 | 0.840 | 0.975 |
| 等权 RRF（原文） | 0.258 | 0.667 | 0.450 | 0.653 |
| adaptive（原文） | 0.541 | 0.858 | 0.840 | 0.975 |
| **adaptive + 多查询** | **0.620** | **0.935** | **0.960** | **1.000** |
| （对照）检索 Agent 选出的 | 0.651 | 0.770 | 1.000 | 1.000 |

- **多查询让 BM25 真正起作用**：英文改写查询与英文摘要有词面重叠，融合后 Precision@5 从 0.84 到 0.96，Recall@10 从 0.87 到 0.93。
- Recall@10 上多查询重排（0.93）高于 Agent 自己选的结果（0.77，Agent 最多选 6 条），说明"Agent 改写查询 + 在全部候选上做混合重排"是比"Agent 自己挑"召回更全的组合；Precision@5 上 Agent 自己挑略高（1.00 vs 0.96）。
- 注意：多查询用到了 Agent 的改写查询，所以它不是独立于 Agent 的方法，而是 Agent 的下游一层。嵌入约 14 万 token/次。经代理访问百炼嵌入会偶发 SSL EOF，评测时对 `aliyuncs.com` 走直连（`NO_PROXY`）。
