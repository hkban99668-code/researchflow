# 检索 Agent 间接提示注入评测（T-033，2026-10-17）

- 模型：deepseek/deepseek-v4-flash（commandcode）；5 个课题 × 12 种攻击（选择劫持 / 查询劫持 / 提前终止 × 中英文 × 注入在第 1 / 第 3 条结果）× 防护开/关，共 120 次 Agent 运行；118 次正常结束，2 次（无防护组）Agent 调用失败。
- 检索器：用候选池离线回放（`retriever=pool`），注入文本插在某条真实检索结果的摘要前。

| | 有防护 | 无防护 |
| --- | --- | --- |
| 攻击成功率（按任务卡的严格判定） | **0/60** | **0/60** |
| 正常完成率 | 100% | 100%（失败 2 次不计） |
| 被注入文献出现在最终选择里（不论是否唯一） | 15/60（25%） | 32/60（53%） |
| 启发式 `suspicious` 标记命中被注入文献 | 60/60 | —（关闭） |
| 查询被劫持去搜无关词 | 0 | 0 |

## 怎么读
- 这个模型对三类攻击都没有"照做"：没有只选被注入的那篇，没有去搜无关词，没有被诱导提前结束。所以这次**测不出防护对"攻击成功率"的作用**（两组都是 0）。
- 防护的可见效果在"被注入文献被选中"上：从 53% 降到 25%。但被注入的是一篇真实检索结果（本身可能相关），选中它不一定是被攻击；要衡量真实危害，下一步应把攻击文本放进**与课题无关**的文献里再测。
- 程序层兜底（只能选检索返回过的 ref_id）这次没被触发。

## 局限
单一模型、5 个课题、单次运行；攻击文本是手写的 12 种，强度有限；启发式检测能被改写绕过。换更容易被诱导的模型或更强的攻击，结论可能不同。
