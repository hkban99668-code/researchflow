## 4. 实现中偏离评审建议的地方

1. **`step_status` 仍为 `dict[str, str]`**（P0-1 相关）。评审建议的 `StepRecord(status="ok", ...)` 已登记在 `core/schemas.py`，但尚未进入 `GraphState`：改成对象会波及第 1 轮已判定的 manifest 结构与 README 描述，结构化程度留给 P1-8。节点失败通过独立的 `error: ErrorRecord | None` 与 `termination` 表达，T-P0-1 所需的 `error.step` 已满足。
2. **`terminal_reason` 从 `GraphState` 移除，但 manifest 仍保留该键**（P0-2 相关）。state 内终止语义统一为 `termination`；manifest 的 `terminal_reason` 由 `termination` 派生（如 `人工审核拒绝：缺失率仍偏高`），以保证 B-6 与第 1 轮结论不回归。
3. **缺失率口径改为行级**（P0-4 相关）。评审只要求「在 dropna 之前计算」，未指定口径；`raw_missing_rate` 定义为「关键列上含缺失的行占比」而非逐单元格占比——按逐单元格口径，T-P0-4 的 40/100 行 NaN 只有 0.1，达不到评审要求的 0.4。行级口径也已同步写进 README §10。
4. **新增规则项 `max_dropped_ratio: 0.5`**（P0-4 相关）。评审建议「新增规则项」，落在 `configs/rules/data_acceptance.yaml`；`precheck` 未收到 `rows_before` 时不校验该项，避免影响既有单测。
5. **`precheck` 保留向后兼容分支**（P0-4 相关）。未传 `raw_missing_rate` 时退化为在传入 frame 上计算，使 5 条既有单测零改动通过。
6. **CLI 兜底使用了 `except Exception`**（P0-1 相关）。`main._state_snapshot` 在 checkpoint 不可读时退化为最小 manifest，因此带一处 `noqa: BLE001`（ruff 规则集未启用 BLE，标记仅为说明）。
7. **`load_rules` 增加了 `model` 参数**（P0-3 相关）。评审建议的无参形式无法区分两份规则文件，实际为 `load_rules(path, *, model=AcceptanceRules | SubmissionRules, required=True)`；`precheck` / `evaluate_submission` 通过 `coerce_rules` 同时接受 dict 与模型，故 `tests/conftest.py` 的两个 dict fixture 未改动。
8. **LLM 重试策略细化**（P0-6 相关）。结构化校验失败立即重试并把错误摘要追加进 messages（不 sleep，避免拖慢测试）；仅 HTTP 5xx 与超时退避（`retry_backoff × attempt`，默认 0.5s）。`max_retries=2` 即最多重试 2 次、共 3 次请求，与设计方案 788 行一致。
